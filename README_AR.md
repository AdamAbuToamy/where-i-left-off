# وين وصلت؟ — Where I Left Off

[![فحوص الجودة](https://github.com/AdamAbuToamy/where-i-left-off/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/AdamAbuToamy/where-i-left-off/actions/workflows/ci.yml)

**احفظ الرابط، سجّل وين وقفت، وارجع وأنت عارف الخطوة الجاية.**

تطبيق لتنظيم المشاريع والدراسة يجمع البطاقات والمجموعات والكورسات والجدول الأسبوعي، مع مزامنة للحساب وتعديلات دون اتصال ومساعد يجهّز التغييرات لمراجعتها.

**[افتح التطبيق](https://where-i-left-off.web.app/)** · **[English](README.md)** · **[قائمة الجاهزية](docs/READINESS_AR.md)** · **[الأمان](SECURITY.md)**

## الحالة الحالية

المساعد متاح للمستخدمين المسجلين ببريد متحقق. يربط كل مستخدم حسابه الخاص في Pollinations من واجهة الموقع، ثم يستخدم المساعد عبر DeepSeek V4.1 Flash. الرصيد المجاني والحصص والتوفر تحددها الخدمة.

نجحت الفحوص الآلية. ما زالت تجربة Google/Pollinations الفعلية، وتثبيت إضافة Chrome من المتجر، وتسليم التنبيهات على أجهزة حقيقية بحاجة إلى تحقق عملي. توضح [قائمة الجاهزية ذات الـ54 نقطة](docs/READINESS_AR.md) ما اختُبر وما بقي وحدود كل فحص.

## الإمكانيات

- بطاقات وأقسام وروابط وملاحظات ونقاط توقف وخطوات تالية وقوائم وتقدم ومواعيد.
- بحث وفلاتر وفرز وعرض أسبوعي ومتابعة عمل اليوم.
- حفظ التعديلات دون اتصال وبقاؤها بعد إعادة التحميل، مع حل صريح للتعارض بعد عودة الاتصال.
- مجموعات ودعوات وإسناد عمل وصلاحيات لأعضاء المجموعة.
- كورسات ومواضيع دراسية وواجبات وامتحانات ومتطلبات سابقة وجدول محاضرات وتمارين ومختبرات.
- مساعد للمحادثة والتلخيص والتعديلات المركبة وإعداد التقارير.
- تنزيل PDF ونص وMarkdown وCSV وJSON.
- التقاط صفحات مدعومة وروابط فيديو بتوقيتها وصفحات Moodle المعروفة، مع معاينة الاستيراد.
- العربية والعبرية والإنجليزية ودعم اتجاهي الكتابة.
- انتقالات للصفحات والبطاقات والنوافذ، وأيقونات متناسقة، ودعم لوحة المفاتيح وتقليل الحركة.
- تطبيق PWA وتنبيهات اختيارية حسب الجهاز وإعدادات النشر.

## البدء

1. افتح الموقع وسجّل الدخول.
2. أضف بطاقة مع الرابط ونقطة التوقف والخطوة التالية.
3. أضف موعدًا أو قسمًا أو قائمة عند الحاجة.
4. افتح الحساب نفسه من جهاز آخر لمتابعة العمل.
5. افتح المساعد واضغط **ربط المساعد**، ثم سجّل ووافق على الربط.

سجّل الدخول أثناء الاتصال قبل الاعتماد على العمل دون إنترنت. تتزامن التعديلات المعلّقة عندما يكون التطبيق مفتوحًا ومتصلًا. المساعد يحتاج اتصالًا بالإنترنت.

راجع [التثبيت على الهاتف](docs/INSTALL.md) و[دليل إضافة المتصفح](browser-extension/README_AR.md).

## كيف يعمل المساعد؟

يرد على المحادثات العادية مباشرة. عند الحاجة إلى بيانات الحساب أو إجراء داخل الموقع، يختار المودل دوال جاهزة بمعاملات محددة. يقرأ الموقع السجلات المسموح بها على دفعات، ويفحص المقترح كاملًا، ثم يعرض **تطبيق التغييرات**. لا يعلن الحفظ قبل تأكيده.

يدعم الطلبات المتداخلة وتفاصيل المتابعة والتواريخ النسبية والإعدادات المسموحة. يُجمّع الرد المتدرج كاملًا قبل فحص الدوال؛ لا تُنفذ أوامر جزئية أثناء وصول الرد. يمكن إيقاف الطلب، ويعرض التشخيص أوقات المراحل دون تضمين الرسائل أو محتوى الحساب أو المفاتيح.

مثال:

> اعمل قسم هالأسبوع وحط فيه بطاقة مشروع البرمجة بتاريخ 28 الشهر، واعمل مراجعة قبلها بيومين، واعطيني PDF بالتغييرات المقترحة.

### حدود مهمة

- زمن الرد والرصيد المجاني متغيران؛ لا توجد خدمة غير محدودة مضمونة.
- البحث في الويب والعثور على أول فيديو YouTube غير متاحين. أعطِ الرابط المباشر عند الحاجة.
- أمان الحساب وأذونات المتصفح وعضوية المجموعات تُدار من واجهاتها الأصلية.
- PDF الحالي صفحات مرسومة، ونصه غير قابل للبحث أو النسخ.
- راجع المقترحات؛ فهم كل صياغة محتملة ليس مضمونًا.

المسار المنشور يستخدم الربط السحابي الخاص بكل مستخدم. التجارب المحلية ومسارات المزوّدين القديمة الموجودة في المستودع محفوظة كتجارب سابقة، وليست إعداد التشغيل الحالي.

## الهندسة

قواعد البطاقات والتخطيط وحالة الجامعة والتنسيق دون اتصال منفصلة عن تكاملات Firebase والمتصفح والمزوّد. منافذ التخزين والاتصال والقفل تُحقن من نقطة التجميع، مع الحفاظ على صيغ البيانات والاستيرادات المتوافقة.

يفحص أمر check:architecture الاعتمادات التشغيلية لأربع نقاط دخول حرجة عبر 14 وحدة، لمنع تسرب أطر الواجهة أو مشغلات المتصفح إلى هذه المسارات.

راجع [المرجع الهندسي](PROJECT_ENGINEERING_GUIDELINES.md)، و[تعليمات المستودع](AGENTS.md)، و[المعمارية](docs/ARCHITECTURE.md)، و[قرار التدفق وفصل الطبقات](docs/adr/2026-10-26-streaming-and-core-boundaries.md).

## التشغيل المحلي

المتطلبات: **Node.js 24** وnpm، و**Java 21** لاختبارات Firestore بالمحاكي.

    npm ci --include=dev
    cp .env.example .env.local
    # ضع إعدادات Firebase العامة الخاصة بك في .env.local
    npm run dev

فعّل Firestore ومزوّدي البريد/كلمة المرور وGoogle، واضبط النطاقات المسموحة وApp Check للنشر المطلوب. لا تضع حساب الخدمة أو المفاتيح الخاصة في ملفات الواجهة أو Git.

للتجربة بالمحاكيات، افتح طرفيتين:

    npm run emulators
    VITE_ASSISTANT_ENABLED=true npm run dev:emulator

اختبارات المتصفح تستخدم حسابات مؤقتة وردود مودل محقونة. الاختبار الحي يحتاج تفويضًا ومفتاح اختبار محدودًا محفوظًا خارج Git. النسخ المستقلة من المشروع تحتاج إعداد Firebase وتطبيق Pollinations خاصين بها.

## النشر

بناء الإنتاج يحتاج إعدادات Firebase وApp Check المناسبة:

    VITE_USE_EMULATORS=false VITE_TEST_OFFLINE=false VITE_REQUIRE_APP_CHECK=true VITE_REQUIRE_FIREBASE_CONFIG=true VITE_ASSISTANT_ENABLED=true npm run build

ينشر مسار Hosting بعد نجاح فحوص الجودة على آخر main، ويشترط نجاحها أيضًا للنشر اليدوي. يحافظ على إعدادات Firebase وApp Check، ولا ينشر مفتاح مساعد مشتركًا.

التنبيهات الاختيارية تعتمد على Cloudflare Worker وD1 وQueues بإعداد مستقل. نشر الموقع لا يستبدل هذا الخادم. راجع [دليل التنبيهات وفحوص الأجهزة](docs/PUSH_NOTIFICATIONS_AR.md).

## نطاق المشروع

المزامنة الدائمة مع حساب Moodle، ومراقبة الردود الخارجية، ورفع المرفقات الثنائية غير متاحة. لا يمكن ضمان محو نسخة مخزنة على جهاز غير متصل عن بُعد. الفحوص العملية المطلوبة والحدود التشغيلية موثقة في قائمة الجاهزية.
