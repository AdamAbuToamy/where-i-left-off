# مساعد WILO: التنفيذ والحدود والفحص

المساعد يقترح عمليات على وظائف الموقع الموجودة، ثم تنفّذها طبقة التطبيق بعد المراجعة. كلام النموذج ليس إثباتًا للحفظ. سجل المهام يعرض حالة كل مهمة، ويأخذ نجاحها من إيصالات التنفيذ، لا من نص الرد.

## الوظائف التي يملك تنفيذها

| جزء الموقع | العمليات المتاحة للمساعد |
|---|---|
| البطاقات | الإضافة، الاسم والخطوة التالية والوصف، الحالة والنوع، نقطة التوقف وقائمة التحقق، الروابط والصورة، تقدم القراءة/المشاهدة، التسليم والمتابعة، النقل بين الأقسام، ترتيب البطاقات، الأرشفة والاستعادة، النقل للسلة والاستعادة |
| الأقسام | إضافة وتسمية وحذف، مع نقل البطاقات المرتبطة قبل حذف القسم |
| الكورسات | الإضافة والتعديل والحذف بعد معالجة الروابط، الملاحظات والرابط والمواضيع وحالتها، المتطلبات السابقة ومواقع الخريطة |
| المهام والامتحانات | الإضافة والتعديل والحذف، نوع المهمة والكورس والتاريخ والوقت والملاحظات والرابط وحالة الإنجاز؛ العناصر المرتبطة بتذكير الهاتف تستخدم محرر الجامعة |
| الجدول الأسبوعي | إضافة وتعديل وحذف المحاضرات والتمارين والمختبرات في الجدول الحالي، تحديد الكورس واليوم والوقت والقاعة والملاحظة؛ اللقاءات أسبوعية بحسب نموذج الموقع |
| الشكل واللغة | الألوان والخلفية واللغة ووضع السكون في المتصفح الحالي |
| التنظيم | الأرشفة التلقائية، التذكيرات، مدة المراجعة، إشعارات سطح المكتب عند وجود إذن المتصفح بالفعل |
| التنقل والعرض | فتح صفحات الموقع، تبويبات الجامعة والكورس، الأرشيف والسلة والمراجعة والأفكار، عرض الأسبوع/البطاقات والبحث والتصفية والأقسام وبطاقاتي في المجموعة، إعادة دليل الاستخدام |
| القراءة والإنتاج | تحليل البيانات المتاحة، التلخيص والنصائح، وإنتاج ملفات نصية قابلة للتنزيل |

تُفحص صلاحية المجموعة على الخادم. تتضمن بيانات السياق الأدوار وأسماء الأعضاء ومعرّفاتهم لتوجيه التعيين، دون إعطاء المساعد صلاحية إضافية. لا يُسمح بكتابة مسارات Firestore عشوائية أو تنفيذ JavaScript من الرد.

## الوظائف التي تُفتح في واجهتها الأصلية

أذونات الإشعارات وتفعيل Push، كلمة المرور وإعادة التحقق، الملف الشخصي وحذف الحساب وتصدير بياناته، إنشاء المجموعات ودعواتها وأدوارها وأعضاؤها وإعلاناتها، الحذف الدائم للبطاقات، جلسات التركيز التفاعلية، اختيار ملفات الاستيراد، قراءة صفحات أخرى عبر الإضافة، وأدوات الإدارة والأمان والنشر.

عند طلب واحدة منها، يجب أن يشرح المساعد الخطوة التي تحتاج إجراء المستخدم ويفتح الصفحة المناسبة عند طلب ذلك. **فتح الصفحة لا يعني تنفيذ العملية الموجودة فيها.** لا يستطيع قراءة Moodle أو ملف محلي أو صفحة خارجية لم يُرسل محتواها إلى الموقع.

## عدة مهام في طلب واحد

- حتى 50 عملية بيانات و20 إجراء واجهة في الرد؛ لا يوجد وعد بعدد غير محدود في دفعة واحدة.
- يمكن استخدام أسماء مؤقتة لإنشاء كورس ثم ربط مهمة أو حصة به في الدفعة نفسها.
- سجل `tasks` يربط كل مهمة بعملياتها أو يذكر المعلومات الناقصة أو الخطوة الأخرى المطلوبة.
- تغييرات البيانات تُحفظ في معاملة Firebase واحدة. إذا رفضت الصلاحيات أو تغيرت البيانات فلا تُحفظ أجزاء من تلك المعاملة.
- إجراءات الواجهة والإعدادات تأتي بعد معاملة البيانات. لها نتائج مستقلة، وتتوقف عند أول فشل، وتظهر الإجراءات التي لم تنفّذ. ليست معاملة واحدة عبر الخادم وتخزين المتصفح.
- إعدادات التنظيم تُحدّث بمعاملة تقارن الحقول المطلوبة وتحافظ على الخيارات الأخرى والتعديلات التي تنتظر المزامنة.
- تراجع البيانات يخضع لفحص النسخة. زر التراجع يعكس تغييرات البيانات المؤكدة؛ إعدادات الجهاز والتنقل لا تدخل في إيصال تراجع البيانات.
- المحادثة نفسها لا تُخزّن في الحساب. إعادة التحميل لا تحذف البيانات المحفوظة.

## فهم الطلبات المركّبة

طلبات إنشاء/تعديل البطاقات والكورسات الحرة تذهب إلى النموذج السحابي؛ لا يحاول تعبير نمطي استخراج الاسم من بقية الجملة. هذا يمنع الاختصار السابق من تحويل «محمد. وضعه في البرنامج…» إلى اسم كورس كامل.

عند وجود قائمة حصص مع مقدمة أو تعليمات إضافية، يقرأ النموذج الرسالة كاملة مع بيانات الحساب. المسار المباشر مخصص لقائمة مغلقة تبدأ مثلًا بـ `Add to the timetable:` ثم عناوين أيام وأسطر حصص فقط؛ أي نثر آخر يعيدها لمسار المحادثة. بذلك لا يُحذف طلب تلخيص أو إنشاء بطاقة لمجرد أنه جاء بعد قائمة حصص. مطابقة هوية الكورسات بالمعنى تبقى متاحة للقوائم المستقلة، ويُطلب من مخطط المحادثة مطابقة الأسماء والأرقام والأسماء المختصرة دون اشتراط تطابق حرفي.

لكل نوع عملية مخطط JSON بحقول وأنواع وحدود محددة، بدل `values` مفتوح. طلب كورس جديد ثم حصة يستخدم معرّفًا مؤقتًا يربط الحصة بالكورس في المعاملة نفسها. سجل المهام مطلوب لتغييرات المحادثة؛ يجب أن يشمل كل عملية مقترحة. هذا يكشف سجلًا ناقصًا من العمليات، لكنه لا يثبت وحده أن النموذج فهم كل جزء لغوي من الطلب.

تخطيط البطاقة الشخصية للأسبوع يعني تحديث `projects.dueDate` بتاريخ حقيقي `YYYY-MM-DD`. فتح أسبوعها يستخدم `navigate` مع `page: personal`, `view: week`, `weekOf` بنفس التاريخ؛ لا تُنشأ حصة جامعية للبطاقة. يعتمد تعبير «25 الشهر» على التاريخ المحلي والمنطقة الزمنية المرسلين مع السياق. الساعة 00:00 مقبولة للحصص.

إذا فشل تنسيق المقترح أو فحص بياناته، تُعاد محاولة واحدة فقط مع الطلب الأصلي والسياق الأصلي والمقترح المرفوض ورمز خطأ ثابت. لا تُحفظ بيانات أثناء التصحيح. تظهر مرحلة انتظار مترجمة، ويظل التطبيق بحاجة للمراجعة. لا يُعاد طلب أخطاء الحساب أو الصلاحيات أو التعارض أو التذكير المرتبط باعتبارها أخطاء نموذج. تُحترم مهلة منع الطلبات المتلاحقة الحالية، ولا تتغير حماية Firebase أو App Check أو حدود المزود.

## الفحص

اختبارات المصدر تغطي المقترح ذي الحصص الـ14، الأيام والأوقات والأنواع، التكرار والغموض، الادعاء الكاذب بالنجاح، عشر عمليات مترابطة، سجل المهام، الإعدادات، الصلاحيات والتعارض والتراجع. اختبارات القبول تستخدم واجهة المحادثة الفعلية وFirestore Emulator لحفظ النتائج وإعادة قراءتها بعد إعادة تركيب الواجهة.

يوجد اختبار Playwright يعيد تحميل المتصفح ويتحقق من الجدول. تعذّر تشغيل Chromium في بيئة التحرير الحالية بسبب منع إنشاء socket؛ نتيجة المتصفح تُراجع في GitHub Actions أو محليًا باستخدام `npm run test:e2e`.

**هذه الاختبارات لا تثبت أن نموذج Qwen يفهم كل صياغة ممكنة.** اختبار الاستنتاج الحي مع مزود Cloudflare أو GPU محلي يحتاج بيئة تشغيله. بعد فشل محاولة التصحيح أو تجاوز السياق، تظهر رسالة خطأ ويعود الطلب إلى مربع الكتابة لإعادة المحاولة. لا تُخفّض حماية Firebase أو App Check لمعالجة خطأ المساعد.

سجل القدرات القابل للتوسعة: `src/assistant/capabilities.ts`، عقد الأوامر: `controlContract.ts` و`actions.ts`، تنفيذ إعدادات الواجهة: `AssistantControls`، حفظ البيانات: `AssistantRepository`، سجل النتائج: `taskLedger.ts`.
