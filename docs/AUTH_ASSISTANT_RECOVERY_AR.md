# استعادة المصادقة وعزل المساعد

## حدود الاستعادة

راجعنا نسخة الجامعة قبل المساعد `1d1daef` والنسخة الأساسية `c79ac9b`. لأن الجامعة والمساعد دخلا main معاً، فإن إعادة الشجرة القديمة بالكامل تحذف خصائص الجامعة الحالية. الاستعادة هنا تعزل دمج المساعد في الإنتاج وتحافظ على الجامعة والبطاقات والتنقل والإشعارات واللغات والبيانات. ليست إعادة ضبط لقواعد البيانات أو رجوعاً كاملاً لكل ملفات المشروع.

المساعد لا يُحمّل ولا يظهر في الإنتاج. يمكن تجربته فقط مع المحاكيات و`VITE_ASSISTANT_ENABLED=true`، داخل حد مستقل للأخطاء. فُصل نقله الشبكي عن خدمة الإشعارات. النشر التلقائي المشترك مع Worker متوقف؛ نشر الواجهة ينتظر نجاح Quality checks على أحدث main. لا تنشر الواجهة نموذجاً عاماً جديداً قبل اختبار الاستدلال الحقيقي.

## المصادقة

شيفرة تسجيل الدخول الأصلية لم تتغير بين نقطة الأساس وبدء فحص الاستعادة. خطأ رابط البريد وحده لا يثبت تلف الحساب: الروابط أحادية الاستعمال، وقد تكون الحالة المخزنة في المتصفح قديمة. أضفنا تحديثاً صريحاً لحالة التأكيد من Firebase وإعادة إصدار الرمز، دون تغيير محلي لقيمة emailVerified.

كان فحص حماية API يفحص نطاقي الموقع فقط، ولا يفحص نطاق Firebase Auth الفعلي `where-i-left-off-b5683.firebaseapp.com`. هذا نقص مثبت في أداة الفحص، لكنه ليس بعدُ إثباتاً لسبب خطأ Google الفعلي. تقرير `auth-origin-report.json` يحدد هل قيد المفتاح ينقصه هذا النطاق. الإصلاح يضيف نطاق المصادقة لنفس المشروع فقط، ويحافظ على قيود الخدمات والطرق، ولا يغيّر enforcement أو App Check أو القواعد أو الفوترة. إذا لم يملك اعتماد النشر صلاحية API Keys، يُسجّل التقرير المرحلة وHTTP status وتستمر استعادة الواجهة؛ لا تُمنح صلاحيات إضافية تلقائياً.

## ما جُرّب

- 3 اختبارات على Auth Emulator: تأكيد رابط جديد، رفض إعادة استعماله، تحديث الحالة وتسجيل الدخول مجدداً، وقبول هوية Google تجريبية. هذه لا تختبر نافذة OAuth الحقيقية.
- 621 حالة تنفيذ وحفظ على Firestore Emulator، منها مصفوفة الأوامر. إجابات النموذج محقونة في هذه الحالات؛ ليست 621 طلباً لمزود ذكاء اصطناعي حي.
- اختبارات فصل المساعد عن الإنتاج، تحديث التأكيد، وإصلاح النطاق دون توسيع صلاحيات الخدمات.
- بناء الإنتاج وفحص lint محلياً. المتصفح المحلي يمنعه نظام التشغيل من إنشاء socket؛ اختبارات Chromium الفعلية تعمل في GitHub Actions ولا تُدّعى محلياً.

لتكرار اختبار محدد فقط: `npm run test:e2e -- tests/browser/layout.spec.ts --grep "he desktop"`. لإعادة آخر حالات فاشلة: `npm run test:e2e:failed`. أصبحت وظائف المتصفح والقواعد والوحدات مستقلة؛ لا تتطلب إعادة وظيفة المتصفح إعادة جميع الاختبارات. إعداد الاختبارات يفرض مشروع demo ويستبدل عناوين المساعد والإشعارات في dist بعناوين غير إنتاجية.

## إعادة بناء المساعد

الواجهة التجريبية تعتمد نموذجاً يختار أدوات typed، وقراءة سياق محدد عند الحاجة، ثم تحققاً في الخادم والعميل من العمليات والمراجع قبل تطبيقها. التنفيذ يستخدم مستودعات الموقع القائمة والحفظ الفعلي. لا تُعتبر رسالة النموذج إيصال نجاح؛ النتيجة تُستخرج من العمليات المحفوظة. الطلب متعدد الخطوات يجب أن يحصي كل خطوة، والاسم الملتبس يستدعي سؤالاً بدل تعديل عنصر خاطئ. الحذف وصلاحيات الحساب لا يتجاوزان قواعد الموقع.

لم يُثبت بعد اختبار المزود الحي بعد هذه الاستعادة، ولا نجاح Google OAuth على الحساب الحقيقي. لا يوجد ضمان فهم كل صياغة أو استخدام سحابي مجاني غير محدود. لا تُفعّل نسخة الإنتاج قبل فحص المزود الفعلي وإنشاء وتعديل وحذف وحفظ وإعادة تحميل واختبارات الطلبات المركبة على حساب اختبار.
