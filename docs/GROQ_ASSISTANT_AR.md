# تشغيل المساعد السحابي عبر Groq

بديل اختياري لـCloudflare Workers AI، باستخدام `openai/gpt-oss-120b` على خوادم Groq. الموقع وFirebase وWorker والتذكيرات يبقون كما هم؛ يتغير مزود الاستدلال فقط. لا يحتاج المستخدمون إلى حساب Groq أو تنزيل نموذج. صاحب الموقع يضع مفتاحًا واحدًا على الخادم.

بحسب [حدود Groq الرسمية](https://console.groq.com/docs/rate-limits) بتاريخ 24 أكتوبر 2026، الحد المجاني المنشور لهذا النموذج: 30 استدعاء/دقيقة، و1,000 استدعاء/يوم، و8,000 توكن/دقيقة، و200,000 توكن/يوم. الحدود الفعلية تظهر في حسابك وقد تختلف. ليست هذه 1,000 رسالة للموقع؛ الرسالة المعتادة تحتاج حصرًا واقتراحًا، وقد تحتاج تصحيحًا إضافيًا. حد التوكن قد ينفد قبل عدد الاستدعاءات. لا نضمن كفاية الحصة لموقع عام أو نجاح/سرعة النموذج دون اختبار حي.

أنشئ حسابًا مجانيًا ومفتاحًا من https://console.groq.com/keys دون تفعيل الدفع. لا تضع المفتاح في الواجهة أو المحادثة أو Git. إذا كان الحساب مفعّل الدفع، لا يستطيع كودنا ضمان أن الاستهلاك مجاني؛ استخدم مؤسسة مجانية وتحقق من صفحة Limits/Billing أولًا. لا يوجد انتقال تلقائي لمزود آخر عند رفض الطلب.

## الاختبار قبل النشر

في Bash على جهاز الإعداد، أدخل المفتاح في مطالبة مخفية، لا ضمن نص الأمر أو سجل الأوامر:

```bash
cd ~/projects/where-i-left-off &&
git pull --ff-only &&
read -rsp 'Groq API key: ' GROQ_API_KEY && echo &&
export GROQ_API_KEY &&
npm run test:assistant:live -- --provider=groq --limit=3 --resume
```

يشغّل اختبار Groq مسار المساعد نفسه مباشرة من Node HTTPS ببيانات اصطناعية، دون Worker محلي أو قاعدة الإنتاج أو تسجيل دخول Cloudflare أو ملف مفتاح مؤقت. يبقى المفتاح في متغير بيئة العملية ولا يظهر في التقرير. التقرير يميز المزود والنموذج. مسار Cloudflare AI وحده يحتاج Worker محليًا وربط AI بعيدًا. لا تشغل 618 طلبًا قبل نجاح التجربة الصغيرة؛ جميع الاستدعاءات تستهلك الحصة.

## النشر بعد نجاح التجربة

من النافذة نفسها، ما دام المتغير موجودًا:

```bash
node scripts/setup-groq-assistant.mjs
```

يرفع السكربت المفتاح عبر stdin إلى Cloudflare Worker Secret، ويحفظ نسخة من الإعداد، ثم يحدد `ASSISTANT_PROVIDER=groq` وينشر Worker الحالي. يحافظ على D1 والطوابير وأسرار Firebase وApp Check. لا يشغّل ترحيل SQL ولا يفعّل فوترة. يحتاج تسجيل دخول Wrangler السابق؛ المفتاح لا يُحفظ في ملف إعداد النشر. يتوقف قبل تغيير المزود إذا فشل رفع السر.

انشر الواجهة بالطريقة المعتادة لتحديث رسائل الخطأ وسياسة الخصوصية، ثم احذف المتغير من جلسة الطرفية:

```bash
unset GROQ_API_KEY
```

يستخدم مسار Groq استدعاء أدوات واحدًا لاختيار كل عمليات الموقع ومعاملاتها؛ لا توجد مرحلة AI مستقلة لحصر الطلبات فيه. يتحقق الكود من المخطط والأنواع والفهارس وتغطية العمليات بسجل الطلبات، ثم يتولى مخطط الموقع التحقق من القيم والمراجع والصلاحيات قبل مراجعة المستخدم والحفظ الذري وإعادة القراءة. جودة استيعاب كل جزء لغوي مسؤولية النموذج؛ فحوص الكود لا تثبت أنه لم يغفل معنى في النص. لا يختصر سياق الحساب بصمت لإخفاء حد الإدخال؛ رفض 413 يعرض سببًا خاصًا ويوقف الاختبار. حدود الدقيقة واليوم للمزود قد ترفض طلبًا حتى قبل بلوغ العدد اليومي.

فحوص الربط المحلية تستخدم HTTP محقونًا: الغلاف الصحيح للمخطط، والمعاملات، والمفتاح على الخادم، وحالات الرفض والرد المبتور، وحفظ إعدادات النشر والتوقف عند فشل رفع السر. لا تثبت جودة الاستدلال الحي؛ ذلك يحتاج مفتاح صاحب الموقع.


## تشخيص اختلاف Node عن Worker المحلي

نجح فحص المستخدم المباشر في Node للاتصال وصيغة حصر أساسية بحالة HTTP 200، بينما أعاد الفحص السابق عبر Worker المحلي خطأً عامًا. هذا لا يثبت بعد نجاح الطلب المركب أو أن Worker هو السبب الوحيد. لذلك نُقل اختبار Groq إلى Node مباشرة، مع إعادة استخدام مسار التنفيذ نفسه في أداة Cloudflare حتى لا تختلف اختبارات الدلالات.

عند الرفض تظهر في الطرفية والتقرير حالة HTTP ورموز مزود مسموحة ومعامل معروف أو رمز شبكة معروف فقط؛ لا تظهر رسالة المزود الخام أو رؤوسه أو محتوى حساب المستخدم. يمكن تمييز HTTP 400 وصيغة JSON عن 401/403 و429 وأخطاء الشبكة. الإلغاء يوقف طلب HTTP الجاري. اختبار CLI آلي يمرر الرسائل الثلاث الأصلية عبر HTTP محقون ثم محلل المساعد ومرجع النتائج، دون Wrangler أو مفتاح حقيقي. لا يعد ذلك استنتاجًا حيًا أو إثباتًا لتشغيل Worker المنشور.


## تبسيط اختيار دوال الموقع

المسار الحالي لـGroq يرسل `tools` مع الدالة `propose_workspace_actions` ومخطط عمليات الموقع الموجودة، ويطلب من النموذج اختيار العملية (`target` و`action`) والمعاملات لكل جزء من الرسالة في دفعة واحدة. الدالة تبني مقترحًا فقط، ولا تنفذ كتابة قبل المراجعة. الأسئلة والملخصات والإجراءات التي تحتاج واجهتها الأصلية تستخدم حقول النص والملفات ونتائج المهام نفسها. اختيار الدالة الفعلي مع جميع العمليات يمر في استدعاء نموذج واحد؛ لم يعد يمر بمرحلة الحصر اللغوي الثانية. مسار Cloudflare السابق لم يُعدّل إلى هذا البروتوكول.

التحقق محلي في الخادم ثم في مخطط العميل: أسماء العمليات والحقول المسموحة، الأنواع والقيم، حدود الدفعة، فهارس المهام، ثم المراجع والصلاحيات والتواريخ والتعارض والحفظ في Firebase. لكل عملية بيانات أو إعداد إشارة في سجل المهام. هذا لا يثبت استيعاب كل صياغة بشرية؛ مجموعة 618 تستخدم مقترحات مكتوبة مسبقًا للتحقق من التوافق، وليست استنتاجًا حيًا. اختبار CLI للرسائل الثلاث يتحقق من استدعاء HTTP واحد لكل رسالة برد أدوات محقون.

أزيل تكرار مخطط JSON في `response_format` من مسار الأدوات، وخُفّض حد الإخراج المعتاد إلى 3072، دون اختصار بيانات الحساب. عند HTTP 429 تُستخرج وحدة الحد (توكن/طلبات، دقيقة/يوم) والأرقام وفترة الانتظار إن ذكرها المزود، دون النص الخام. الطلب الذي يتجاوز وحده حد توكن الدقيقة يُعرض كطلب كبير؛ الانتظار لن يصلحه. الحد المؤقت مع `retry-after` حتى 15 ثانية يُعاد مرة واحدة فقط ضمن مهلة HTTP الإجمالية البالغة 40 ثانية. لا إعادة تلقائية عند انتهاء الحصة اليومية أو غياب معلومات كافية.


## إعادة فحص رد محفوظ دون استدعاء النموذج

إذا نجح النموذج في اختيار كل القيم ثم ظهر `oracle-request-omitted`، فقد يكون الفحص القديم رفض تجميع عدة حقول في بند خطة واحد. المصحح يفحص القيم المطلوبة بعد مخطط العمليات الفعلي، لا عدد بنود عرض النموذج. تظل القيم الناقصة والملاحظات على بطاقة مختلفة والسجلات أو تفضيلات الجهاز غير المطلوبة أسباب رفض. الالتزامات غير المرتبطة بكتابة بيانات، مثل الإجابة أو الخطوة التي تحتاج واجهتها الأصلية، تبقى مطلوبة في سجل الخطة. سُمّي عداد الواجهة «بنود الخطة»، فهو لا يثبت وحده عدد الطلبات المفهومة.

أعد تقييم آخر رد أدوات مسجل، دون مفتاح أو اتصال بمزود AI:

```bash
node scripts/recheck-assistant-report.mjs
```

يقرأ `assistant-acceptance-live-report.json` ويكتب نتيجة منفصلة في `assistant-acceptance-rechecked-report.json`، مع `liveInferenceCalls:0`. لا يعدّل التقرير الأصلي، ولا يكتب في حسابك أو يحفظ بيانات الإنتاج. يمكن تمرير مسار تقرير سابق كأول معامل. إذا نجح فحص المقترح، انتقل إلى إعداد النشر ثم جرّب التطبيق والحفظ وإعادة الفتح في الموقع نفسه.
