# إشعارات مجانية للتطبيق المثبّت — Cloudflare Free

هذه النسخة تستبدل حزمة Firebase Blaze السابقة. لا تُشغّل `setup-push.mjs` القديم ولا تنشر وظائف Firebase للإشعارات. يبقى الموقع وAuth وFirestore على خطة Spark؛ خدمة الإرسال فقط على Workers Free مع D1 وQueues. لا تُفعل Workers Paid أو أي إضافة مدفوعة.

## ما تعمل به الميزة

- صفحة إشعارات تظهر من التطبيق المثبّت فقط، مع موافقة صريحة وإذن نظام الهاتف.
- مواعيد المهام الشخصية وبطاقات المجموعات المسندة للمستخدم، وساعة افتراضية أو مخصصة، وتكرار أسبوعي اختياري.
- تذكير قبل الموعد بربع ساعة/ساعة/يوم أو في الموعد نفسه.
- تذكير بالبطاقات المهملة بعد 7/14/30/60/90 يومًا، مع حد تذكير مهمل واحد للحساب يوميًا؛ هذا النوع معطل افتراضيًا.
- ساعات هدوء ومنطقة زمنية، وإخفاء أسماء البطاقات على شاشة القفل افتراضيًا.
- إيقاف للهاتف أو لكل الأجهزة، وتخصيص كل بطاقة، وتجربة إشعار. خمسة أجهزة كحد أقصى للحساب.
- الضغط يفتح البطاقة. التفاعل مع بطاقة/فتح رابطها والتعديل عليها يحسب نشاطًا، ومجرد ظهور البطاقة على الشاشة لا يحسب زيارة.

## التكلفة والحدود

بحسب توثيق Cloudflare في 20 أكتوبر 2026، يمكن استخدام Workers Free دون بطاقة دفع. تشمل الخطة حدودًا يومية: Workers حتى 100,000 طلب، D1 حتى 5 ملايين صف مقروء و100,000 صف مكتوب، وQueues حتى 10,000 عملية يوميًا (الإشعار الواحد قد يستخدم عدة عمليات طابور). هذه حدود تشغيل وليست وعدًا بعدد مستخدمين أو إشعارات. توجد حدود أخرى مثل وقت CPU للخطة المجانية.

عند استنفاد الحصص في الخطط المجانية قد تتوقف الخدمة حتى تجددها؛ لا يُطلب من السكربت ترقية الخطة تلقائيًا. أبقِ Firebase Spark وWorkers Free دون حساب فوترة/بطاقة. قراءات Firestore التي تنفذها خدمة التذكير تدخل أيضًا في الحصة المجانية لمشروعك، ويمكن أن تؤثر على إتاحة التطبيق إذا استُنفدت.

هذه خدمة صغيرة ذات حصص مجانية، وليست خدمة غير محدودة أو ضمانًا لوصول جميع التذكيرات. أول اختبار على Cloudflare والهاتف ضروري للتحقق من ملاءمة حدود CPU لحجم بياناتك. لا تتوفر قياسات أداء الإنتاج من الاختبارات المحلية.

مصادر: https://www.cloudflare.com/products/workers/ وhttps://developers.cloudflare.com/workers/platform/limits/ وhttps://developers.cloudflare.com/d1/platform/pricing/ وhttps://developers.cloudflare.com/queues/platform/pricing/

## 1. مفتاح قراءة Firebase فقط — لا حاجة لتفعيل Blaze

الخدمة تحتاج قراءة تاريخ المهمة وحالتها حتى عندما يكون التطبيق مغلقًا. لا نفتح قاعدة البيانات للعامة ولا نرسل كلمات مرور المستخدمين. تُحفظ بيانات الإشعارات في D1، وتُقرأ المهام من Firebase عند إعادة الجدولة وقبل التسليم.

1. افتح https://console.cloud.google.com/iam-admin/serviceaccounts?project=where-i-left-off-b5683
2. أنشئ حساب خدمة باسم `wilo-push-reader` في مشروعك الحالي.
3. امنحه هذين الدورين فقط: **Cloud Datastore Viewer** (`roles/datastore.viewer`) و**Firebase Authentication Viewer** (`roles/firebaseauth.viewer`). لا يحتاج Owner أو Editor أو صلاحيات كتابة.
4. افتح الحساب → Keys → Add key → Create new key → JSON. احفظ الملف في Downloads خارج مجلد Git.
5. لا ترسل ملف JSON في المحادثة ولا تضفه إلى GitHub. سيقرأه سكربت الإعداد من مساره المحلي ويرفعه مباشرة إلى Secret في Worker.

قد تمنع سياسة مؤسسة إنشاء مفاتيح حسابات الخدمة. إذا حدث ذلك فلا تعطل السياسة تلقائيًا؛ استخدم حسابًا/مشروعًا يسمح بإعداد مناسب أو أوقف الميزة. لا يحاول السكربت تغيير سياسات IAM أو الخطط المدفوعة.

## 2. الإعداد من Ubuntu بعد تطبيق الحزمة

```bash
cd ~/projects/where-i-left-off
npm ci
npm ci --prefix push-worker
npm run lint
npm test
npm test --prefix push-worker
node scripts/setup-free-push.mjs
```

السكربت التفاعلي سيطلب:

- **Cloudflare Account ID** (32 حرفًا/رقمًا) من لوحة حسابك.
- المسار المحلي لملف reader JSON، مثل `/mnt/c/Users/ID140/Downloads/your-reader-key.json`.
- Firebase Web App ID إذا لم يجده في `.env` أو `.env.local`.
- تسجيل الدخول إلى Cloudflare في المتصفح عبر Wrangler، ثم رابط Worker المطبوع بعد النشر.

سيجهز قاعدة D1 وQueue، ويولد مفتاح VAPID، وينشر Worker، ويرفع المفتاح الخاص وreader JSON كأسرار، ثم يكتب رابط الخدمة العام في `public/push-config.json`. لا يطبع الأسرار، ولا يغيّر خطة Firebase، ولا يطلب شراء دومين أو نقل الموقع.

أبقِ `push-worker/.push-private.json` في مكان آمن محليًا خارج أي مشاركة، واحتفظ بنسخة آمنة منه. هو مستثنى من Git، كما أن `wrangler.local.json` مستثنى. لا تُولد زوج VAPID جديدًا عند إعادة النشر؛ تغيير المفتاح يتطلب إعادة اشتراك الهواتف. لا تنشر القيم الخاصة في `VITE_` أو public/.

قد يطلب أول نشر تحديد نطاق workers.dev لحسابك. اختر النطاق الفرعي المجاني، دون شراء دومين أو خطة. إذا ظهر طلب ترقية مدفوعة فتوقف؛ لا حاجة لها للتصميم الحالي.

النطاقات المسموحة افتراضيًا هي `https://where-i-left-off.web.app` و`https://where-i-left-off.firebaseapp.com`. إذا كان مستخدموك يدخلون من نطاق مختلف أضفه إلى `APP_ORIGINS` في `push-worker/wrangler.local.json` وأعد نشر Worker. لا تستخدم نجمة عامة بدل القائمة.

## 3. نشر الموقع

بعد اكتمال السكربت:

```bash
VITE_TEST_OFFLINE=false bash scripts/deploy-production.sh
```

الموقع يرسل Firebase ID Token وApp Check إلى Worker. الخدمة تتحقق من التوقيع وissuer وaudience ومعرف Web App. لا يوجد وضع إنتاج يسمح بتجاوز App Check. لا حاجة لتخفيف Firestore rules أو إضافة صلاحيات كتابة من المتصفح.

أوامر إعادة نشر Worker لاحقًا، دون إعادة توليد المفاتيح:

```bash
node push-worker/node_modules/wrangler/bin/wrangler.js deploy --config push-worker/wrangler.local.json
```

## 4. تجربة الهاتف الحقيقي

1. أغلق التطبيق وافتحه من أيقونته لتحديث service worker.
2. الإعدادات → الإشعارات → تفعيل → اسمح من النظام → إرسال إشعار تجريبي.
3. اضبط بطاقة بتاريخ اليوم وساعة بعد خمس دقائق، واحفظ إعدادات تذكيرها، وتأكد من انتهاء مزامنة المهمة. عطّل ساعات الهدوء مؤقتًا للاختبار.
4. أغلق التطبيق وانتظر، ثم اضغط الإشعار وتأكد من فتح البطاقة.
5. جرّب إكمال المهمة/حذفها قبل الموعد، والإيقاف المحلي، وإعادة فتح التطبيق، والخروج وتبديل الحسابات. الحساب السابق لا يجب أن تظهر إشعاراته على الهاتف.
6. افتح الموقع في تبويب عادي: رابط إعدادات الإشعارات مخفي.

iPhone يحتاج تطبيقًا مضافًا للشاشة الرئيسية وiOS 16.4 أو أحدث. Push ليس منبهًا مضمونًا بالثانية؛ الشبكة وأوضاع التركيز والبطارية وحدود الخدمة قد تؤخره. تحديث Cron جديد قد يحتاج حتى 15 دقيقة للانتشار أول مرة. اختبار الإرسال محدود بواحد في الدقيقة للهاتف.

## آلية الجدولة والاعتمادية

المجدول يقرأ فهرس المواعيد المستحقة من D1، ثم يرسل أعمالًا صغيرة إلى Queue. لكل مساحة شخصية/مجموعة موعد فحص قادم محسوب من أقرب مهمة أو تذكير بطاقة مهملة؛ لا يقرأ جميع بطاقات جميع المستخدمين كل دقيقة. يجري فحص احتياطي يومي، ويوقظ التطبيق الخدمة بعد مزامنة تغييرات المستخدم. عند فتح التطبيق أو عودة الإنترنت، تُعاد محاولة المزامنة.

تغييرات المجموعات التي ينفذها مستخدم آخر قد تحتاج إشارة مزامنة من تطبيقه أو الفحص الاحتياطي؛ إذا غُيّر موعد إلى وقت أبكر دون وصول إشارة مزامنة للخدمة، قد يتأخر اكتشافه. الخدمة تعيد قراءة البطاقة قبل التسليم، لذلك لا تعتمد على نص قديم في الطابور. لا يمكنها إرسال تعديل محلي لم تتم مزامنته مع Firebase.

وقت المعالجة المجاني محدود؛ يتعامل المجدول مع عشرة نطاقات استحقت في الجولة، ويجهز المخطط ثمانية أحداث جديدة في العمل الواحد، والباقي في جولة لاحقة. لذلك قد تتأخر دفعات كبيرة من المواعيد المتزامنة. هذه حدود معلنة للنسخة المجانية.

هناك قفل لكل نطاق وسجل حجز لكل حدث وتسليم لمنع التكرار. الحجز قبل الإرسال يعني احتمال فوات رسالة عند تعطل العملية بعد الحجز؛ لا نزعم تسليمًا مضمونًا أو exactly-once. رسائل Push لها TTL ساعة. يُهمل الموعد بعد مرور 24 ساعة، ولا تُرسل مواعيد سابقة لتفعيل الحساب. تُؤجل الرسائل خلال الهدوء. تُحذف اشتراكات 404/410، وتزال بيانات الحساب من D1 عند اكتشاف حذفه أو تعطيله؛ قد ينتظر هذا الفحص القادم حتى يوم.

حماية الاشتراكات: مالك واحد لكل endpoint، والتحقق مجددًا قبل التسليم، وبوابة محلية في service worker تمنع عرض إشعارات حساب مختلف بعد الخروج/التبديل. نقاط Push محصورة بخدمات المتصفحات الموثوقة ولا تُتبع التحويلات الخارجية. لا تُقبل عناوين رسائل يختارها عميل لإرسالها إلى مستخدمين آخرين.

## اختبارات التطوير

```bash
npm test --prefix push-worker
node push-worker/node_modules/wrangler/bin/wrangler.js deploy --config push-worker/wrangler.jsonc --dry-run --outdir /tmp/wilo-worker-check
node push-worker/node_modules/wrangler/bin/wrangler.js d1 execute wilo-push --local --file push-worker/schema.sql --config push-worker/wrangler.jsonc
```

تغطي الاختبارات SQLite حقيقية مطابقة لمخطط D1، والجدولة، وملكية الاشتراك، وإعادة التحقق قبل التسليم، والإلغاء، ومحتوى القفل، وفك تشفير الرسالة بمكتبة مستقلة والتحقق من توقيع VAPID. تستخدم اختبارات الخدمة تحقق هوية ومصدر بيانات وهميين؛ لا تثبت اتصال الإنتاج أو صلاحيات IAM. توقيعات المستخدم وApp Check في الإنتاج تتحقق بمفاتيح Google العامة عبر jose. الاختبار الحقيقي بعد النشر مطلوب.

## حالة التحقق من هذه النسخة

نجح البناء وlint و137 اختبارًا للتطبيق و22 اختبارًا لخدمة Cloudflare. نجح تجميع Worker بالحجم المضغوط نحو 24 KiB وتنفيذ مخطط D1 محليًا. لا تمثل هذه النتائج تجربة دفع على الهاتف أو اختبار حصص Cloudflare الإنتاجية. لم يُسجل دخول إلى حسابك ولم تُنشَر الخدمة فعليًا بعد.

نجح أيضًا فحص HTTP داخل workerd: طلب OPTIONS مسموح، ورفض طلب بلا هوية، ورفض نطاق خارجي، وتشغيل المشغّل المجدول على D1 محلية.


### شكل إشعارات الهاتف
- يستخدم شريط الحالة رمزًا أحادي اللون من هوية التطبيق.
- صورة شفافة تمنع Chrome من وضع حرف W بدل صورة الإشعار الإضافية. قد يختلف عرضها بين الهواتف.
- إشعار التجربة يظهر باللغة المحفوظة في التفضيلات.
- اسم التطبيق وعنوان الموقع في ترويسة الإشعار يحددهما النظام؛ لا يتحكم بهما قالب رسالة الويب.
- يستخدم الإرسال redirect: manual المتوافق مع Workers ويرفض ردود إعادة التوجيه.
