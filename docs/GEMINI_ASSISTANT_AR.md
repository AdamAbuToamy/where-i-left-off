# تشغيل Gemini مباشرة بدل Groq

المزود الاختياري الجديد هو Google مباشرة، بالنموذج `gemini-3.5-flash-lite`. لا استدعاء Groq أو تبديل تلقائي إلى مزود آخر. يستخدم نفس دفعة دوال الموقع والتحقق والمراجعة والحفظ في Firebase.

المصادر الرسمية بتاريخ 24 أكتوبر 2026:
- https://ai.google.dev/gemini-api/docs/pricing : للنموذج طبقة مجانية محدودة؛ ليست خدمة غير محدودة. حد المشروع الفعلي في Google AI Studio.
- https://ai.google.dev/gemini-api/docs/openai : endpoint المتوافق مع OpenAI، استدعاء الدوال، ورمز Gemini في ترويسة Authorization.
- https://ai.google.dev/gemini-api/docs/deprecations/ : تقييد وصول المشاريع الجديدة إلى نماذج 2.5؛ لذلك لا يستخدمها هذا التغيير.

اختر مشروع Free Tier في Google AI Studio دون تفعيل الفوترة. أنشئ مفتاحًا واحدًا لصاحب الموقع؛ لا يحتاج كل مستخدم مفتاحًا. لا تضعه في المحادثة أو الواجهة أو GitHub. بيانات الشات والسياق ترسل إلى Google؛ سياسة الطبقة المجانية تسمح باستخدام المحتوى لتحسين منتجات Google. يتطلب استخدام الإنتاج مراجعة ملاءمة هذه السياسة لبيانات المستخدمين.

```bash
cd ~/projects/where-i-left-off &&
git pull --ff-only &&
npm ci --prefix push-worker &&
read -rsp 'Gemini API key: ' GEMINI_API_KEY && echo &&
export GEMINI_API_KEY &&
node scripts/setup-gemini-assistant.mjs &&
bash scripts/deploy-production.sh
```

قبل أي تغيير في الخادم، يجري السكربت طلبًا حيًا اصطناعيًا إلى Google باستخدام بروتوكول أدوات الموقع مع التحقق المحلي الكامل، ويتحقق من اختيار إنشاء بطاقة بالاسم والتاريخ والملاحظة الصحيحة. لا يقرأ حسابك ولا يحفظ بطاقة. إذا فشل الاتصال أو المخطط أو الحصة يتوقف قبل رفع السر وتغيير المزود. نجاح هذا الفحص يثبت طلبًا اصطناعيًا واحدًا؛ لا يثبت كل الصياغات أو عمل الحفظ في الإنتاج.

بعد النجاح يرفع السر مباشرة إلى Cloudflare ويجهز جداول المساعد ويحافظ على Firebase وApp Check والطوابير، ثم ينشر Worker ويتحقق من الإصدار وCORS. انشر الواجهة لتحديث تسمية النموذج والخصوصية ودعم نتيجة فحص Gemini. اختبارات CI تستخدم ردودًا محقونة ولا تثبت توفر النموذج في مشروع Google الخاص بك. المفتاح والحساب الحقيقيان مطلوبان للفحص الحي.

## اختبار فعلي من GitHub دون حاسوب

الخادم يدعم Gemini، وأداة `test:assistant:live` أصبحت تقبله أيضاً. لا تعتبر اختبارات الردود المحقونة دليلاً على فهم النموذج الحي.

1. من Settings → Secrets and variables → Actions في المستودع، احفظ مفتاح **صاحب الموقع** في repository secret اسمه `GEMINI_API_KEY`. لا تضعه في المحادثة أو ملفات الكود. استخدم مشروعاً مجانياً دون تفعيل فوترة مدفوعة. هذا المفتاح للاختبار، وليس مفتاحاً لكل مستخدم، ولا يغيّر إعداد Worker المنشور تلقائياً.
2. من Actions افتح **Assistant live validation** ثم Run workflow. اختر `gemini` و`smoke`، وأكّد استخدام مشروع مجاني. يشغّل ثلاث رسائل اصطناعية بالعربية والإنجليزية والعبرية؛ لا يقرأ حسابات المستخدمين ولا يكتب في الموقع. بعد نجاح الاستدلال، ينفّذ الردود نفسها في Firestore Emulator بمستودع الحفظ الحقيقي ويعيد قراءتها، دون استبدالها بالإجابات المتوقعة. نجاح اقتراح النموذج وحده لا يعني نجاح هذه المرحلة. النشر إلى main يفحص الجاهزية فقط ولا يستدعي النموذج تلقائياً.
3. حمّل artifact باسم `assistant-live-report`. تقرير not-run يعني أن الاستدلال لم يحدث. نجاح smoke يثبت الرسائل الثلاث فقط؛ التقرير يحتفظ أيضاً بعدد بقية الحالات التي لم تُفحص. اختيار full يشغّل مصفوفة 618 طلباً ويتوقف عند حدود المزود؛ ليس وعداً بتجاوز الحصة.

لتصحيح حالة واحدة بدلاً من إعادة كل الاختبارات، ضع ID في case_id في workflow، أو شغّل محلياً:

```bash
npm run test:assistant:live -- --provider=gemini --case=compound-card-ar --resume
```

الأداة تستخدم المفتاح من متغير البيئة `GEMINI_API_KEY` وتُرجع خطأ واضحاً إذا غاب. الفحص الحي لم يُنفّذ في جلسة التطوير إذا لم يكن المفتاح متاحاً لها. يبقى المساعد معطلاً في الإنتاج حتى تحقق الاستدلال والتنفيذ والحفظ الحقيقي. Gemini المجاني يخضع لحصص، وليس خدمة بلا حدود، وقد تستخدم Google بيانات طبقته المجانية لتحسين منتجاتها؛ هذه الاختبارات تستعمل بيانات اصطناعية فقط.
