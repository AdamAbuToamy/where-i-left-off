# تحليل فشل المساعد ومصفوفة القبول

## ما تثبته الصورة وما لا تثبته

الرسالة `ai-incomplete-proposal` تأتي من فحص اكتمال المقترح داخل Worker، بعد محاولة التصحيح. بحسب مسار الخادم، يكون الطلب قد اجتاز التحقق من الحساب وApp Check ووصل إلى مسار AI. ليست هذه الرسالة دليلاً على رفض قواعد Firebase للحفظ، ولا تكشف الرد الخام الذي صدر عن النموذج. لذلك لا يمكن تحديد المخالفة الدقيقة في طلب الصورة من الصورة وحدها.

أُعيد إنتاج خطأين في فحص النسخة السابقة بعمليات صحيحة: رفض تجميع إنشاء البطاقة وموعدها وملاحظتها في سجل مهمة واحد، ورفض إنشاء البطاقة ثم إضافة الملاحظة بتعديل آخر على اسمها المؤقت. كان الفحص يقارن شكل تقسيم النموذج للعمليات وعدد/ترتيب مهامه، ويتطلب نوع العملية حرفيًا، رغم تكافؤ النتيجة. هذه أخطاء في التطبيق وليست برهانًا على ضعف النموذج.

## الإصلاح

- حصر الطلبات مستقل عن اقتراح العمليات؛ لا يتحدد العدد من كلام المنفّذ عن نفسه.
- تركيب تعديلات كل سجل قبل مطابقة الآثار المطلوبة. يُقبل إنشاء البطاقة مع كل حقولها، أو إنشاؤها ثم تعديلها في الدفعة نفسها.
- بناء سجل المهام من المطابقة الفعلية؛ لا يُرفض تعديل صحيح لأن النموذج جمع المهام أو أعاد ترتيبها أو أهمل بيانات عرضها.
- حل مراجع الكورسات/الأقسام الجديدة بين مفاتيح المخطط وأسماء المنفذ المؤقتة. تُفحص روابطها الحقيقية بعد ذلك بمنفذ الموقع.
- مقارنة المواعيد الجامعية بلحظتها الفعلية عند اختلاف UTC/offset، والمتطلبات السابقة كمجموعة، والأرشفة/السلة كحالة ذات وقت غير صفري.
- إلحاق الملاحظة يحافظ على النص السابق. غياب الموعد أو الملاحظة، والعنصر الملتبس، والكتابة الإضافية غير المرتبطة، والملف المطلوب الغائب تبقى أسباب رفض.
- محاولة التصحيح تتلقى أسبابًا محددة وأرقام الطلبات والحقول، دون بيانات حساب خام في السجل التقني. عند استمرار الرفض تُعرض تفاصيل آمنة مترجمة بدل رسالة عامة فقط.
- الانتقال لنموذج الحساب/كلمة المرور يظل خطوة مساعدة، ولا يتحول إلى ادعاء تنفيذ تغيير الحساب.

## مراجعة طبقات الأعطال

| الطبقة | أسباب محتملة | ما يفصلها عن غيرها |
|---|---|---|
| واجهة الإرسال | قفل انتظار، وضع محلي غير جاهز، حدث إرسال، تغير الحساب | فحوص الواجهة والهوية، عدم إرسال الرسالة للسحابة تلقائيًا عند اختيار المحلي |
| Auth وApp Check وAPI | رمز منتهي، مشروع/تطبيق مختلف، مستخدم غير متحقق، نطاق غير مسموح | اختبارات التوقيع والعزل؛ الخطأ في الصورة صادر بعد هذه المرحلة |
| السياق | معرّفات قديمة، تعديلات غير متزامنة، تجاوز 44 ألف حرف، محتوى مصدر مستورد غير مرسل | قراءة جديدة للحساب، فحص pending والحجم، علامة sourceOmitted |
| فهم اللغة | ضم طلبين، اسم يتضمن «ثم»، نفي، ضمير مبهم، كورس بعنوان أطول، تاريخ نسبي | حالات لغوية ومراجع فعلية؛ **جودتها الحية تحتاج تشغيل المزود الحقيقي** |
| واجهة المزود | حصة مجانية، انقطاع، بطء، إخراج مبتور، صيغة JSON غير مقروءة | رموز مستقلة، حدود إخراج، تقرير استنتاج حي؛ لا استنتاج سرعة من المحاكاة |
| فحص المقترح | تطابق حرفي زائد، اختلاف تقسيم العمليات، ترتيب السجل، اختلاف تمثيل الوقت، مرجع اسم مؤقت | أُعيد إنتاج الرفض الخاطئ؛ المطابقة الجديدة تقارن الآثار والهوية |
| منفذ البيانات | حقل غير مسموح، تاريخ مستحيل، نهاية قبل البداية، دورة متطلبات، مرجع مفقود، تذكير مرتبط | نفس كيانات الموقع والتحقق من المخطط؛ لا كتابة مسارات عشوائية |
| الصلاحيات والحفظ | عضوية/دور، تغير سجل، خروج المستخدم، انقطاع بعد الإرسال | معاملة، حراسة النسخ، إعادة قراءة من الخادم قبل إعلان الحفظ |
| واجهة النتيجة | فتح الأسبوع بلا موعد، خلط عدد السجلات بعدد الطلبات، نجاح لفظي دون إيصال | سجل طلبات منفصل وإيصالات حفظ وعرض القيم المحفوظة |
| التحديث والنشر | Worker قديم مع واجهة أحدث، إعداد endpoint، Service Worker مخزّن | نشر الطرفين وإعادة فتح الصفحة؛ نجاح CI ليس إثباتًا لتحديث الإنتاج |
| الحدود الوظيفية | Push/أذونات المتصفح، كلمة المرور، حذف الحساب، الأدوار، إجراءات غير منشورة | الواجهة الأصلية وخطوة واضحة؛ مراجعة كاملة في ASSISTANT_UI_AUDIT_AR.md |
| حجم الدفعة | أكثر من 50 عملية بيانات أو 20 إجراء واجهة | رفض واضح؛ لا وعد بدفعات غير محدودة |

هذه مراجعة للأسباب المعروفة ومسارات الكود، وليست إثبات استبعاد كل عطل شبكي أو كل صياغة بشرية ممكنة.

## مجموعة الطلبات

`tests/fixtures/assistant/corpus.mjs` يحتوي **206 سيناريوهات × 3 لغات = 618 رسالة فريدة**. تشمل كل حقول التعديل المنشورة، إنشاء الأنواع الخمسة، حذف العناصر المسموح بها ونقل البطاقة للسلة، إعدادات الموقع، 126 توليفة من طلبين على البطاقة نفسها، إنشاء كورس ثم حصة، قسم ثم بطاقة، عشر بطاقات، حذف كورس مع توابعه، منتصف الليل، أسماء حرفية تحتوي «ثم»، والطلب المصوّر بآثاره الثلاثة.

لكل رسالة مرجع نتائج محدد مستقل عن نص النموذج. تمر الردود المحقونة عبر مطابقة الآثار ثم محلل الرد ومنفذ البيانات الحقيقيين. فحص الحفظ يزرع حسابًا اصطناعيًا منفصلاً، يطبق التغييرات بصلاحياته على Firebase Emulator ثم ينشئ قراءة جديدة من الخادم للتحقق من القيم والحذف. إجراءات الجهاز تُفحص بعقد الأوامر، ولا تسمّى محفوظة في Firestore؛ اختبارات منفذ الإعدادات منفصلة.

**هذه الـ618 ليست 618 استجابة حقيقية من النموذج.** إنها اختبارات تنفيذ وقبول بمخرجات مزود محقونة. محاولة الاستنتاج الحي في بيئة التحرير توقفت عند عدم تسجيل الدخول إلى Cloudflare، قبل إرسال أي طلب للنموذج؛ صفر اختبارات استنتاج حي مكتملة هنا.

## تشغيل النموذج الحقيقي من جهاز الإعداد

```bash
npm run test:assistant:live -- --limit=618 --resume
```

يستخدم تسجيل دخول Wrangler على جهازك، وWorker محليًا على loopback مع ربط AI بعيد رسمي، وبيانات اصطناعية فقط. لا يستخدم Firestore/D1/طوابير الإنتاج، ولا ينشر endpoint عامًا، ولا يقرأ محتوى حسابك. يحتاج `wrangler login` فقط إذا لم يكن جهاز الإعداد مسجّلًا بالفعل.

يحفظ `assistant-acceptance-live-report.json`: كل طلب، نجاحه أو فشله، زمنه، ومراحل الحصر والاقتراح والتصحيح ببيانات الاختبار الاصطناعية. علامة البطء تتجاوز 20 ثانية وليست قياسًا مفترضًا. يتوقف عند انتهاء الحصة، ويخرج برمز فشل/عدم اكتمال، ولا يعد الطلبات غير المنفذة ناجحة. الاستكمال يتجاوز النجاحات السابقة من نفس إصدار المجموعة والمنفذ والنموذج. عند تغير الإصدار يُؤرشف التقرير السابق تلقائيًا ويبدأ تقرير جديد. لا ترقية تلقائية أو نموذج مدفوع بديل. قد تتطلب مئات طلبات AI حصصًا من عدة أيام؛ لا وعد باكتمالها ضمن حصة يوم واحد.

للعرض دون استنتاج: `node scripts/test-assistant-live.mjs --list`.


## نتيجة التقرير الحي المرفق وإصلاح الترميز

التقرير الفعلي يحتوي 618 محاولة: 14 ناجحة، و64 رفضًا لصيغة الحصر، وخطأين في النتيجة، و538 خطأ اتصال بالمزود دون استجابة مسجلة. لا يثبت التقرير أن هذه الـ538 أخطاء فهم أو نفاد حصة؛ سبب المزود الأصلي لم يكن مسجلًا.

من حالات الصيغة الـ64، كانت 61 استجابة JSON خارجية صحيحة، لكن عقدنا كان يطلب ترميز القيمة داخل سلسلة JSON ثانية. فهم النموذج أسماء البطاقة والموعد والملاحظة ثم رفضها محللنا. صار العقد يطلب `expected` بقيمته الفعلية ونوعه، مع توافق للردود السابقة، وتعريف أنواع الحقول وقيمها المسموحة، ومنها نوع البطاقة `kind`.

أُعيد تشغيل الحصر المسجل للحالات الـ64 دون استدعاء جديد للنموذج: أصبح 57 منها مقبولًا. هذه نتيجة فحص الحصر فقط، وليست 57 عملية حفظ مكتملة. بقيت سبع حالات مسجلة مرفوضة لاقتطاع الرد، أو اختراع مقطع مصدر، أو قيمة مصفوفة غير صحيحة. أُضيف توجيه مصدر النطاقات ومحاولة تصحيح واحدة للحصر غير الصالح، وحدود إخراج بحسب حجم الطلب؛ نجاحها مع النموذج الحي يحتاج إعادة اختبار.

يوقف المشغّل الاختبار فور خطأ الحصة أو صلاحية المزود، وبعد ثلاثة أخطاء عدم توفر متتالية. يسجلها كمحاولات محجوبة، لا كفشل فهم، ويسجل مرحلة خطأ المزود برمز آمن. لا يعرض بيانات الاعتماد.

ابدأ بثلاث رسائل البطاقة المركبة بالعربية والإنجليزية والعبرية، قبل إعادة المئات:

```bash
npm run test:assistant:live -- --limit=3 --resume
```

لا توجد نتيجة استنتاج جديدة بعد هذا الإصلاح من بيئة التحرير؛ الاختبارات المحلية تستخدم الردود المسجلة والمحاكاة.
