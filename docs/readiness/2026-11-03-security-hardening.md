# WILO — تطبيق نقاط حماية الفيديو

التاريخ: **2026-11-03**. المرجع: الفيديو المرفق، ومدته 63 ثانية، بعد مراجعة الصوت والصورة.

## النتيجة

إصلاحات النطاق اجتازت الفحوص وأصبحت جاهزة للنشر المحدد. **لا أعلن إغلاق جميع التنبيهات الأمنية:** تبقى 27 نتيجة متوسطة في أدوات تطوير التطبيق. فحص مكتبات تشغيل التطبيق وفحص العامل كاملًا بلا نتائج. لا نتائج عالية أو حرجة في الفحص الحالي.

حافظت على الدخول والبيانات والصلاحيات والأوفلاين والمقترحات الذرية. لم أستبدل Firebase Authentication بنظام كلمات مرور أو كوكيز جديد. تفاصيل الإصدار المباشر في ملف `2026-11-03-security-hardening-production.json` المجاور.

## الإصلاحات الفعلية

- قراءة جسم الطلب تدريجيًا وتحديد حجمه بالبايت قبل تجميعه، حتى مع غياب Content-Length أو كذبه. رفض JSON التالف والأجسام البدائية والمصفوفات وUTF8 غير الصالح. حد مسار ارتباط المساعد 500000 بايت ليستوعب السياق متعدد اللغات؛ وبقية المسارات 65536 بايت.
- حدود ذرية في D1 لكل حساب: 120 طلب حالة، و12 تغيير ارتباط، و30 طلب استدلال خلال الدقيقة. لا تختلط حصص الحسابات أو أنواع الطلبات. تُحذف سجلات الحد عند حذف الحساب. تُعرض رسالة انتظار عند تجاوز حد الموقع، دون اعتباره إلغاءً للمفتاح أو نفادًا لرصيد المزود.
- اشتراط exp وiat صالحين في App Check، إضافة إلى فحص التوقيع والمشروع والتطبيق القائم.
- إضافة HSTS وPermissions-Policy للموقع، وترويسات حماية لعامل API. الميكروفون مسموح للموقع نفسه، حفاظًا على تفريغ الجلسات.
- تسجيل أسباب رفض المصدر وتجاوز الحد بفئات آمنة فقط، وتفعيل Workers Logs مع تعطيل سجلات الاستدعاء الآلية وtraces. لا محتوى حساب أو مفاتيح في السجلات، ولا رسائل بريد أو تنبيهات خارجية جديدة.
- فحص امتداد ونوع وحجم نسخة الجامعة ثم مخطط البيانات القائم. استبدال خطأ JSON التقني برسالة مفهومة. هذا فحص طرفي مكمل لقواعد Firestore، وليس بديلًا عنها.
- تحديث undici في أدوات العامل من 7.29.1 إلى 7.30.1، مع lockfile وفحص توافق العامل. لم أستخدم audit fix --force أو تخفيضًا عشوائيًا للأدوات.
- توسيع كشف الأسرار في المصدر والأصول لمفاتيح sk_/gsk_، وإضافة ماسح لسجل Git لا يطبع محتوى أي سر. أُدرج الفحص في CI مع جلب التاريخ الكامل.

## الاختبارات المنفذة

- **1255 اختبار تطبيق ناجحًا /117 ملفًا** عبر `npm test`.
- **885 اختبار عامل ناجحًا** عبر `node --test push-worker/*.test.mjs`.
- **680 اختبار Firestore ناجحًا /15 ملفًا** على المحاكي وJava 21.
- **4 اختبارات استعادة دخول ناجحة** على Auth Emulator، بما فيها استعادة كلمة المرور واستخدام الرمز مرة واحدة.
- **4 رحلات متصفح ناجحة:** ربط الحساب في حاسوب وهاتف وإعادة التحميل؛ سحب زر الهاتف ومعاينة التغيير؛ dock الحاسوب؛ رفض الملفات غير المناسبة وJSON التالف وفحص XSS والحفظ وإعادة التحميل.
- أول تشغيل لرحلة الاستيراد فشل بسبب إعداد الاختبار الذي أعاد اللغة للإنجليزية. صُححت تهيئة الاختبار وأعيد تشغيل الرحلة بنجاح، دون تخفيف تحقق المنتج. الرحلات الثلاث الأخرى نجحت في التشغيل الأول.
- TypeScript وبناء الإنتاج وفحص المفاتيح والنشر الجاف للعامل: ناجحة.
- فحص البنية: 22 وحدة، دون انتهاكات.
- lint: لا أخطاء؛ تحذير سابق واحد في cleanup الخاص بـrequestGeneration في AssistantWidget.

لم تُجرَ طلبات مزود AI حيّة، ولم يُستهلك رصيد المستخدم. لم يُنفذ اختبار جهاز فعلي iOS/Android أو تغيير بيانات حسابات الإنتاج. فحص سجل Git نمطي؛ لا يغطي كل تنسيق سر محتمل أو objects غير القابلة للوصول.

## المتبقي

27 نتيجة متوسطة في أدوات التطوير، ضمن سلاسل minimatch وglob وuuid وOpenTelemetry وESLint وFirebase CLI. لا نتائج عالية أو حرجة في الفحص الحالي، لكن هذه التنبيهات **غير مغلقة**. يلزم إصلاح مدعوم أو ترقية منسقة مع اختبارات التوافق، بدل override رئيسي يكسر واجهات CJS أو أمر إصلاح قسري.

ملف `docs/knowledge/university/university_rules.md` غير موجود؛ لم أدّع قراءته. طُبقت تعليمات AGENTS وPROJECT_ENGINEERING_GUIDELINES الموجودين.

## النشر والتراجع

أُضيف جدول حدود D1 بأمر IF NOT EXISTS، ثم نُشر العامل ثم Hosting. الجدول مرتبط بالحساب ولا يمس المشاريع أو المقررات. يمكن الرجوع إلى إصدار العامل وHosting السابقين دون حذف جدول الحدود أو جدول المفاتيح المشفّر. لم تتغير قواعد Firestore أو طرق الدخول أو مفتاح تشفير الارتباط القائم.

أدلة الإصدار المباشر في `2026-11-03-security-hardening-production.json`.
