# Wilo quality, appearance and local load — 2026-11-11

## Capability in this release

- Settings → Site colors → Color mode: System / Light / Dark, translated into Arabic, Hebrew and English. Choice is per account on this browser, following existing appearance persistence; bootstrap remembers the last browser choice. System mode responds to OS changes and cross-tab preferences. Critical inline styles apply dark colors before application JavaScript; existing palettes/backgrounds remain available. Browser theme-color follows illumination. The SPA, loader, account settings, cards/editors, university, groups, notifications and API documentation use existing design tokens. Standalone static marketing/legal pages retain their separate stylesheet.
- Search now matches every word regardless of order, case, Arabic/Hebrew combining marks and excess whitespace; searches descriptions as well as existing card fields. Ctrl/Cmd+K or / focuses search outside editors and modal dialogs. Escape and existing clear controls remain supported.
- Sync details explain queued/offline/local-copy behavior without changing queues, conflict resolution or persistence. Reopening/keeping Wilo online is still required to finish client-side sync. Scheduled server reminders remain independent of an open browser.

## Repeatable local load

Run `npm run test:load:local -- /tmp/wilo-load.json` with installed Node 24. This makes **no network requests**: real API routing, API-key hashing/scopes/revocation, SQLite-in-memory limits/audit, existing task planners and existing scheduler run against injected memory repositories/account checks/Push. It is not Firestore/D1 network latency, provider capacity, Cloudflare load, real phone delivery or a production benchmark.

The recorded sample is `docs/benchmarks/2026-11-11-local-load.json`: 1087 requests, 23 synthetic accounts, 20 in-flight read requests; 60 accepted and 20 rate-limited in a frozen synthetic minute; independent 401/403/404 checks for revoked key, missing scope and cross-account resource access; four concurrent creation retries produced one course. Scheduler input of 300 cards produced 300 unique synthetic dispatches over 38 forced due ticks and zero extra dispatches on immediate scheduler replay. Existing limit of eight queued notifications per account/cycle remains unchanged; clustered deadlines can therefore be delayed across cycles. Never interpret these numbers as a real-world delivery-time guarantee.
